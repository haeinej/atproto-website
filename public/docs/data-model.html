Data model

Posts and cortex knowledge are separate data. A post maps to a vault row, a public repository record and a Markdown file. Memories, notes, skills and tools have private, member-scoped storage of their own.

ohm is in development. These docs cover the implementation and the work still planned. Built does not mean verified on the live service; see Status and limits.

slugStringThe last segment of the post's address. Mutable. Unique within a vault
label, sublabelStringWhere the post is filed, in the author's own words

title, subtitleString, optional

bodyMarkdownAs the author wrote it
connectList, up to 32Other posts or web pages this post follows from

sourceObject, optionalWhere the post first appeared, if elsewhere: platform, address, and the platform's own ID
siteObject, optionalFields of the author's own site, outside the shared schema
propertiesObjectAnything else the author gave it. Stored, and never published

Identifiers and versions

FormPurpose
Post ID13 characters that sort by creation time, in the form the AT Protocol uses for record keysIdentity. Renaming or refiling a post does not change it. It is also the record key when the post is published
Versionv followed by a SHA-256 digest of the post's contentConcurrency control. Every write names the version it replaces. A mismatch is refused with Changed and the current version
SequenceA counter per vault, advanced by every changeIncremental sync. listPosts with since returns only what changed after a cursor, removals included

A removed post keeps its row with no version, so a client that asks what changed is told that it went.

The published record

A public post is one record of type com.ohmmmm.post in the member's repository, stored under the post's ID. The schema is fixed and the same on every site.

FieldTypeMeaning
bodyString, requiredCommonMark with footnotes. media:ID as an image destination places an attachment
publishedAtDatetime, required
canonicalUrlURI, requiredThe post's address on the author's website
title, subtitleString
updatedAtDatetimeWhen the post last changed after it was published
slugStringThe last segment of the address
label, sublabelStringFree-form, as the author named them
formStringThe kind of object, derived from the content: writing, note, image, gallery, video, audio, file, media, link, embed, quote, list, code or other
connectList of URIsAT URIs or web addresses of what the post follows from
linkObjectFor a link or embed: the page as it described itself
sourceObjectWhere the post first appeared, if not on the author's site
mediaListAttachments, each with an ID unique within the post
siteObjectSite-specific data, namespaced by its own $type

visibility and properties are not part of the record. A post that is not public has no record.

Attachments

An entry in media is an image, a video, an audio recording or a file. Each carries a file, which is a blob stored in the member's repository, and may carry sourceUrl, the address the original came from.

KindAcceptsAdditional fields
imageimage/*alt, caption, width, height
videovideo/*poster, caption, durationMs
audioaudio/*caption, durationMs
fileapplication/*, text/*caption

In the vault, a post references its attachments by address. The copy in the repository is made when the post is published. Mirror and publish

Storage

The service stores posts, account links and cortex data. Every cortex table is scoped by the member's DID; a memory name, skill name or observation ID is never a cross-member address.

TableKeyHolds
postsAccount DID and post IDThe post as JSON, its version and sequence, and indexed copies of the fields the repository tree is drawn from
linksohm user ID, with the DID uniqueWhich AT Protocol account an ohm account works in, and when its published posts were first mirrored
cortex_memoriesDID and memory nameCurrent JSON, revision, sequence and removal state
cortex_memory_versionsDID, name and earlier versionPreserved memory text; rewrites and removals retain the prior row atomically
cortex_notesDID and note IDObservation, originating session, project, authenticated author and immutable outcome receipt
cortex_skillsDID and skill nameInstructions and supporting files; approval names one exact version
cortex_toolsDID and tool nameSettings or inert proposals; no credentials or executable configuration
cortex_turns, cortex_turn_receiptsDID and turn IDReserved storage for the unbuilt turn-capture adapter

The database enforces unique keys and conditional updates. Memory history is preserved by a trigger in the same statement as a rewrite or removal. Restoring earlier text creates a new revision, so an old concurrency token does not become current again.

Context

getContext seeds identity, vault-map and working-style. Its always array contains full {memory, version} entries; vault-map also includes current service-derived vault structure and recent posts. Other memories are indexed by name, description and kind.

Approved skill descriptions, enabled non-proposed tool descriptions, pending notes and the waiting-turn count complete Context. Its version changes with its inputs. A project field records scope, but the planned automatic prompt-recall request is not implemented; callers must not assume automatic project filtering or a context budget.

The post schema and profile schema are unchanged by cortex data. Nothing in these private tables is published as com.ohmmmm.post.
