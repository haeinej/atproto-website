Service API

The vault and cortex service registers 38 requests in 15 capabilities. This reference includes authenticated placeholders and is generated from the tables the service runs on.

ohm is in development. These docs cover the implementation and the work still planned. Built does not mean verified on the live service; see Status and limits.

Conventions

The vault and cortex service speaks XRPC, the request convention of the AT Protocol. Every request has a namespaced name and is sent to /xrpc/ followed by that name. Cortex requests are private; a registered request can still be an authenticated NotBuiltYet placeholder.
Base addresseshttps://vault.ohmmmm.com, and https://app.ohmmmm.com/vault for the workspace, where the ohm session cookie is in scope
ReadsGET, with parameters in the query string
ChangesPOST, with parameters as a JSON body
ResponsesJSON, sent with Cache-Control: private, no-store. getAttachment answers with the file itself
IdempotencyVersioned writes name the version replaced; identical retries are safe. Notes reuse client-made IDs and retain settlement receipts. A multi-request tool can partially complete, so reread state before retrying after a failure
AuthenticationA service token from the member's PDS in Authorization: Bearer, or an ohm session. Identity and access

The access level of each request is one of four.

AccessCredential
PublicNone. The response contains only public information
Any authenticated accountA service token from any PDS, issued for this request
MemberA service token from the member's own PDS, or an ohm session connected to that account
Member, with an ohm sessionAn ohm session only. A change must also originate from ohm's own pages

Posts

Read and change the posts in a vault, one at a time. Every change names the version it replaces, so two edits never overwrite each other unseen.

com.ohmmmm.vault.listPosts

Every post with the version it is at. With since, a point an earlier list returned, only what changed after it, removals included.
MethodGET
AccessMember
Parameterssince: optional: the cursor of an earlier list
Returnsposts (id, version, slug, label, sublabel, visibility, title), cursor, and more when there is another page

com.ohmmmm.vault.getPost

One post in full, and its version.
MethodGET
AccessMember
Parametersid: the post's ID
Returnspost, version

com.ohmmmm.vault.putPost

Saves one post. replaces is the version being replaced and is left out for a new post. Sent twice, it ends the same as sent once. Whatever the post says about who may see it, only this copy changes.
MethodPOST
AccessMember
Parameterspost: the whole post
replaces: optional: the version it replaces
Returnsid, version, and unchanged when nothing differed

com.ohmmmm.vault.deletePost

Removes one post, for good.
MethodPOST
AccessMember
Parametersid: the post's ID
replaces: the version being removed
Returnsid, removed

Structure

The shape of a vault: its labels, the sublabels inside them, and a line for each post. Enough to draw it or decide where something belongs, without reading any post in full.

com.ohmmmm.vault.getTree

Labels, sublabels, and each post with who may see it, what kind of thing it is, the platform it first appeared on if that was somewhere else, and why it cannot be published, if it cannot.
MethodGET
AccessMember
ParametersNone
Returnsposts, public, friends, private (counts), and labels, each with its posts and sublabels

Search

Find posts by the words in them, at every visibility. A title counts for more than a label, and a label for more than the body.

com.ohmmmm.vault.searchPosts

The posts that mention every word of q, best first, each with a passage that shows where.
MethodGET
AccessMember
Parametersq: the words to look for
visibility: optional: only posts at this visibility
limit: optional: how many, 10 unless said, 50 at most
Returnsfound, and posts (id, slug, title, label, sublabel, visibility, date, passage)

Mirror

Bring what the member has already published on their PDS into the vault. It only reads the PDS, and it never changes a post the member has since changed in the vault.

com.ohmmmm.vault.importPublished

Reads the member's repository and says what it holds as posts: how many, which would differ from what is published, and what could not be kept. With apply, saves them. Without it, changes nothing.
MethodPOST
AccessMember
Parametersapply: optional: save the posts
site: optional: the member's website, when it is not the one their handle names
from: optional: one older post type to read, when it should not be found
Returnssite, types, records, posts, sameAsPublished, differs, lost, cannotBePublishedYet, skipped, applied; and with apply, saved, unchanged, changedThere, refused

Publish

Work out what would have to change in the member's own repository for what is published to match their vault. The service changes nothing there and holds no permission to: the member, signed in at their own PDS, makes the changes from the list. Only the shared post type is touched, and a record the vault knows nothing about is never removed.

com.ohmmmm.vault.getPublishPlan

What publishing would do: the posts it would publish for the first time, replace and take down, the ones that cannot be published and why, and the published records the vault knows nothing about. With prepare, also the changes themselves, ready to be made.
MethodGET
AccessMember
Parametersprepare: optional: 1 to include writes, the changes to make
Returnsrepository, pds, collection, create, replace, remove, unchanged, cannot, notInVault, changes (how many); and with prepare, writes and plan, a name for exactly these changes

com.ohmmmm.vault.getAttachment

One file that one of the member's posts places, fetched from where the post says it is. It answers with the file itself, not JSON. It is for publishing, which sends a copy of each such file to the member's PDS.
MethodGET
AccessMember
Parametersid: the post's ID
attachment: the name the post's record places the file under
ReturnsThe file, with its type

com.ohmmmm.vault.exportFiles

Account

For a member signed in to ohm: who they are, and which AT Protocol account their vault is. One ohm account works in one AT Protocol account, and the other way round. These ride on the ohm session only; a token from a PDS does not reach them.

com.ohmmmm.account.get

Who is signed in, the AT Protocol account they connected if they have, and whether what it had published has been brought in.
MethodGET
AccessMember, with an ohm session
ParametersNone
Returnsuser (name), did, mirrored, and service: who a PDS has to address its token to when the member connects

com.ohmmmm.account.connect

Ties an AT Protocol account to the ohm account. token is one the account's PDS issued for this request and nothing else.
MethodPOST
AccessMember, with an ohm session
Parameterstoken: a token from the account's PDS, issued for this request
Returnsdid, and already when it was connected before

com.ohmmmm.account.disconnect

Unties the AT Protocol account. The vault is kept, and opens again when the account is connected.
MethodPOST
AccessMember, with an ohm session
ParametersNone
Returnsdid, now empty

Identity

The first steps of signing in: finding an account from its handle, and saying who a token from a PDS names. Neither touches a vault.

com.ohmmmm.identity.findAccount

Finds an account from what a person types to sign in: their handle, or their DID. Needs no sign-in, and answers only with what is public.
MethodGET
AccessPublic
Parametersaccount: a handle, such as example.com, or a DID
Returnsdid, handle, pds, and service: this service's own DID

com.ohmmmm.identity.whoAmI

Says who a token from a PDS names. The token has to be issued for this request and nothing else, so only its holder can ask.
MethodGET
AccessAny authenticated account
ParametersNone
Returnsdid, and handle when the handle points back to the account

Memory

Private memories for the authenticated member. Every rewrite names the version it replaces and preserves that earlier version.

com.ohmmmm.cortex.listMemories

List memory descriptions and versions, with a stable cursor. With since, include changes and removals.
MethodGET
AccessMember
Parameterssince: optional: an earlier cursor
kind: optional: person, preference, project or reference
Returnsmemories (name, version, description, kind, writtenBy, when), cursor, and optionally more

com.ohmmmm.cortex.getMemory

Read a memory in full. An optional version reads a preserved earlier version; putMemory can restore it with the current replaces value.
MethodGET
AccessMember
Parametersname: the memory name

history: optional: 1 to list earlier versions and their authors and times
Returnsmemory, version, and with history=1, earlier (version, writtenBy, when, replacedAt)

com.ohmmmm.cortex.putMemory

Save the whole memory, naming the version it replaces. The service sets writtenBy from the authenticated principal and retains its own seen counters. Repeated writes are safe.

Returnsname, version, and unchanged when nothing differed

com.ohmmmm.cortex.deleteMemory

Remove a memory, naming its current version. Earlier text remains private in history; the removal is included in the next incremental list.
MethodPOST
AccessMember
Parametersname: the memory name
replaces: the version being removed
Returnsname, removed

com.ohmmmm.cortex.searchMemories

Find memories mentioning every word of q. A description counts more than the body. Ties are ordered by name.
MethodGET
AccessMember

limit: optional: 10 unless said, at most 50
Returnsmemories (name, description, kind, passage), best first

Notes

Private observations with client-made IDs and immutable explicit settlement receipts. The member’s agent judges; the service makes no model calls.

com.ohmmmm.cortex.addNote

Record one observation without changing memory. The service records the authenticated author and time. Retrying the same ID and content is safe; reusing an ID for different content is refused.
MethodPOST
AccessMember
Parametersid: a client-made ID, at most 200 characters
note: one nonempty line, at most 500 characters
session: the originating session, at most 200 characters
project: optional: repository, at most 2,000 characters
Returnsid

com.ohmmmm.cortex.listNotes

List unsettled observations, oldest first. With settled=1, include immutable receipts and kept observations to compare across sessions.
MethodGET
AccessMember
Parameterssettled: optional: 1 or true to include settled notes
Returnsnotes (id, text, session, project, writtenBy, when, and if settled, settledAt and outcome)

com.ohmmmm.cortex.settleNotes

Atomically record from 1 to 100 explicit outcomes: kept, dropped or a memory name with its current version. Each note is settled once. Memory evidence counts distinct originating sessions and preserves earlier memory versions; retries do not count twice.
MethodPOST
AccessMember
Parametersnotes: 1–100 distinct {id, outcome, version?}; a memory outcome requires the current memory version
Returnssettled (the note IDs acknowledged)

Errors

A refusal is JSON with an error code from the table below and a message written to be shown to a person as it is.

ErrorStatusCause
SignInRequired401The request rides on an ohm session, and there is none
AccountChanged409The authenticated DID differs from X-Ohm-Did, the member displayed by the editor. Reopen before reading or changing content
AuthRequired401The token is missing, cannot be read, was issued for another request or service, has run out, or its signature does not match
NotAMember403The account has not been let in yet
WrongOrigin403A request that changes something came with a session but not from ohm's own pages
NotConnected409The ohm account has no AT Protocol account connected yet
AlreadyConnected409The ohm account already works in another AT Protocol account
ConnectedElsewhere409The AT Protocol account is already connected to another ohm account
SignInUnavailable503ohm's sign-in could not be reached to check a session
MethodNotFound404There is no such request
WrongMethod405The request is the other of GET and POST
InvalidRequest400The request is not JSON, or something it says is not what that request takes
InvalidPost400The post is not one the vault can hold. The message lists every reason
InvalidMemory400The memory is not one the cortex can hold, or its source notes do not belong to this member. The message says why
InvalidSkill400The skill or its supporting text files do not fit the cortex rules. The message says why
SkillNotApproved403An agent asked for skill instructions whose current version the member has not approved
InvalidTool400The tool setting or proposal is not valid. Credentials and executable configuration stay outside the cortex
InvalidCursor400since is not a value an earlier list returned
NotFound404There is no such post, cortex item or saved version
Changed409The post or cortex item has changed since the version the request names. The answer carries the current version
SlugTaken409Another post in the vault already has that slug
NameTaken409A cortex item already has that name; read it and name its version to replace it. A tool proposal cannot replace an existing tool
NotBuiltYet501The cortex request is registered and authenticated, but its implementation has not been built yet
TooLarge413The post is more than 600 KB of text, or a file it places is empty or larger than 25 MB
FileUnreachable502A file a post places could not be fetched from where the post says it is
AccountNotFound404No AT Protocol account answers to that handle or DID
NoRepository400The account's DID document does not say where its repository is kept
RepositoryUnreachable502The account's PDS would not answer
InternalError500Something went wrong in the service itself

Agent tools

An agent's tools are compositions of the requests above and add no capability of their own. Each runs on the member's machine and authenticates as the member, with a service token per request.

ToolEffectRequests used
cortex_startReadcom.ohmmmm.cortex.getContext
cortex_noteChangecom.ohmmmm.cortex.addNote
cortex_settleChangecom.ohmmmm.cortex.listNotes, com.ohmmmm.cortex.getMemory, com.ohmmmm.cortex.putMemory, com.ohmmmm.cortex.settleNotes
cortex_recallReadcom.ohmmmm.cortex.searchMemories, com.ohmmmm.cortex.getMemory
cortex_rememberChangecom.ohmmmm.cortex.getMemory, com.ohmmmm.cortex.putMemory
cortex_forgetChangecom.ohmmmm.cortex.getMemory, com.ohmmmm.cortex.deleteMemory
cortex_skillReadcom.ohmmmm.cortex.getSkill
cortex_propose_skillChangecom.ohmmmm.cortex.getSkill, com.ohmmmm.cortex.putSkill
cortex_propose_toolChangecom.ohmmmm.cortex.proposeTool
vault_treeReadgetTree
vault_listReadgetTree
vault_readReadgetTree, getPost
vault_searchReadsearchPosts
vault_saveChangegetTree, getPost, putPost
vault_set_visibilityChangegetTree, getPost, putPost
vault_statusReadgetPublishPlan
vault_publishChangegetPublishPlan, getAttachment
vault_mirrorChangeimportPublished
vault_deleteChangegetTree, getPost, deletePost

The server that offers these tools is described in Agent integration. Vault tools follow these rules.

  1. A new post is private. Marking it for anyone else is a separate, confirmed step.
  2. Changes that others can see take two calls. The first returns what would happen and a confirm value bound to exactly that outcome. Only a second call carrying the value proceeds.
  3. A post is changed from the version that was read. If it has changed since, nothing is saved.

Cortex memory and note writes need no approval queue. Forgetting uses its own single-use confirmation. Agents can propose skills and tools, but approval and tool settings require the linked member's ohm session.
